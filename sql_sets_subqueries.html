1 UNION и UNION ALL

Оба операнда должны возвращать одинаковое число столбцов и совместимые типы. По умолчанию UNION убирает дубликаты строк; UNION ALL — оставляет все.

UNION

Объединение как множество: повторяющиеся строки схлопываются.

UNION ALL

«Склеить списки»: быстрее, если дубликаты нужны или не страшны.

Задание 1.1

Выведи все пары (nickname, score) из обоих хакатонов одним списком без повторяющихся строк. Подпиши столбец года не нужно — только nickname и score.

SELECT nickname, score FROM hackathon_2024
UNION
SELECT nickname, score FROM hackathon_2025
ORDER BY nickname, score;

Строка pixel_fox, 87 и pixel_fox, 90 — разные строки, обе останутся. Если бы score совпадал, UNION оставил бы одну.

Задание 1.2

Тот же запрос, но через UNION ALL. Сколько строк вернётся? Сравни с заданием 1.1.

SELECT nickname, score FROM hackathon_2024
UNION ALL
SELECT nickname, score FROM hackathon_2025;
Ответ

8 строк (4 + 4). UNION ALL не удаляет дубликаты — всегда полное «склеивание».

Задание 1.3

Собери общий рейтинг: nickname, team, score, и литерал '2024' или '2025' как season. Отсортируй по score по убыванию.

SELECT nickname, team, score, '2024' AS season FROM hackathon_2024
UNION ALL
SELECT nickname, team, score, '2025' AS season FROM hackathon_2025
ORDER BY score DESC;

2 INTERSECT и EXCEPT

INTERSECT — строки, которые есть в обоих результатах. EXCEPT — строки из первого запроса, которых нет во втором (в Oracle часто пишут MINUS, в SQLite — EXCEPT).

SQLite: INTERSECT и EXCEPT поддерживаются; порядок столбцов и типов снова должен совпадать.
Задание 2.1

Никнеймы участников, которые были и в 2024, и в 2025 (достаточно одного столбца nickname).

SELECT nickname FROM hackathon_2024
INTERSECT
SELECT nickname FROM hackathon_2025
ORDER BY nickname;
Результат

byte_bard, code_ninja, pixel_fox (3 строки)

Задание 2.2

Никнеймы, которые были в 2024, но не участвовали в 2025.

SELECT nickname FROM hackathon_2024
EXCEPT
SELECT nickname FROM hackathon_2025;
Результат

stack_overflow

Задание 2.3

Команды (team), которые встречались в 2025, но не фигурировали в 2024 (сравни только столбец team).

SELECT team FROM hackathon_2025
EXCEPT
SELECT team FROM hackathon_2024
ORDER BY team;
Результат

Delta, Gamma

3 Подзапрос в WHERE

Подзапрос в скобках возвращает одно значение, список или таблицу — и внешний запрос использует его в условии.

Задание 3.1 — скalar

Ученики, у которых есть попытка по модулю «Subquery Dungeon» (id = 3) с баллом выше среднего по этому модулю.

Сначала мысленно: средний балл по module_id = 3 для score (55, 88, 91) → 78.
SELECT l.name, p.score
FROM learners l
JOIN progress p ON p.learner_id = l.id
WHERE p.module_id = 3
  AND p.score > (
      SELECT AVG(score) FROM progress WHERE module_id = 3
  );
Результат
namescore
Борис88
Глеб91
Задание 3.2 — IN

Имена учеников из Москвы, которые сдавали хотя бы один модуль с difficulty >= 4.

SELECT name
FROM learners
WHERE city = 'Москва'
  AND id IN (
      SELECT p.learner_id
      FROM progress p
      JOIN modules m ON m.id = p.module_id
      WHERE m.difficulty >= 4
  );
Результат

Борис (модуль 3 и 4), Вика — только модули 1–2, не попадает. Итого: Борис.

4 Подзапрос в FROM

Вложенный SELECT создаёт временную таблицу (производную). Ей нужен алиас.

Задание 4.1

Для каждого ученика — средний балл по всем его попыткам. Выведи только тех, у кого средний балл > 80. Колонки: name, avg_score.

SELECT l.name, stats.avg_score
FROM learners l
JOIN (
    SELECT learner_id, ROUND(AVG(score), 2) AS avg_score
    FROM progress
    GROUP BY learner_id
) AS stats ON stats.learner_id = l.id
WHERE stats.avg_score > 80
ORDER BY stats.avg_score DESC;
Результат (avg_score > 80)
nameavg_score
Диана91.5
Борис83.33

5 Подзапрос в SELECT

Скalar-подзапрос в списке SELECT должен возвращать одно значение на каждую строку внешнего запроса (или коррелироваться — см. уровень 7).

Задание 5.1

Для каждого модуля выведи title и общее число записей в progress по этому модулю (подзапрос с COUNT(*)).

SELECT m.title,
       (SELECT COUNT(*) FROM progress p WHERE p.module_id = m.id) AS attempts
FROM modules m
ORDER BY attempts DESC;
Задание 5.2

Для каждого города — число учеников (простой подзапрос не нужен; повтори через подзапрос в SELECT для тренировки: список городов и (SELECT COUNT(*) FROM learners l2 WHERE l2.city = l1.city)).

SELECT DISTINCT city,
       (SELECT COUNT(*) FROM learners l2 WHERE l2.city = l1.city) AS cnt
FROM learners l1
ORDER BY cnt DESC, city;

Здесь подзапрос уже коррелирован (l1.city из внешнего запроса). На уровне 7 разберём это глубже.

6 EXISTS, ANY, ALL

EXISTS проверяет, вернул ли подзапрос хотя бы одну строку (часто внутри — SELECT 1). ANY / ALL сравнивают значение с набором из подзапроса.

Задание 6.1 — EXISTS

Ученики, у которых есть хотя бы одна завершённая попытка (completed = 1).

SELECT l.name
FROM learners l
WHERE EXISTS (
    SELECT 1 FROM progress p
    WHERE p.learner_id = l.id AND p.completed = 1
)
ORDER BY l.name;

Все пять учеников имеют completed = 1 хотя бы в одной строке, кроме проверки: Аня имеет module 3 с completed 0, но 1 и 2 — с 1. Все попадают.

Задание 6.2 — NOT EXISTS

Ученики, которые ни разу не открывали модуль «Window Wizard» (id = 4).

SELECT name
FROM learners l
WHERE NOT EXISTS (
    SELECT 1 FROM progress p
    WHERE p.learner_id = l.id AND p.module_id = 4
);
Результат

Аня, Вика, Диана

Задание 6.3 — ALL

Найди попытки по модулю 1, где балл строго больше, чем у всех остальных попыток по модулю 1 (классический «рекорд побил всех»).

SELECT p.learner_id, p.score
FROM progress p
WHERE p.module_id = 1
  AND p.score > ALL (
      SELECT score FROM progress
      WHERE module_id = 1 AND learner_id != p.learner_id
  );
Результат

learner_id = 2 (Борис), score = 90

Задание 6.4 — ANY

Модули, для которых существует попытка с баллом 95 (хотя бы одна строка в progress с таким score).

SELECT title
FROM modules m
WHERE 95 = ANY (SELECT score FROM progress WHERE module_id = m.id);
Результат

JOIN Quest (Диана набрала 95)

7 Коррелированные подзапросы

Внутренний запрос ссылается на строку внешнего (l.id, m.id…). Для каждой строки снаружи подзапрос выполняется заново.

Задание 7.1

Для каждого ученика выведи имя и его лучший балл среди всех модулей (коррелированный подзапрос с MAX в SELECT).

SELECT l.name,
       (SELECT MAX(p.score) FROM progress p WHERE p.learner_id = l.id) AS best_score
FROM learners l
ORDER BY best_score DESC;
Задание 7.2

Строки из progress, где балл выше среднего по этому же модулю (сравнение с коррелированным AVG).

SELECT p.learner_id, p.module_id, p.score
FROM progress p
WHERE p.score > (
    SELECT AVG(p2.score)
    FROM progress p2
    WHERE p2.module_id = p.module_id
)
ORDER BY p.module_id, p.score DESC;
Задание 7.3

Ученики, у которых нет ни одной попытки с баллом ниже 70 (коррелированный NOT EXISTS на «плохие» оценки).

SELECT l.name
FROM learners l
WHERE NOT EXISTS (
    SELECT 1 FROM progress p
    WHERE p.learner_id = l.id AND p.score < 70
)
ORDER BY l.name;
Результат

Борис, Вика, Глеб, Диана (у Ани есть 55 по модулю 3)

★ Босс-файт

Финальное задание

Один запрос: никнеймы, которые участвовали в обоих хакатонах и хотя бы раз набрали score ≥ 90 в любом году. Подсказка: комбинируй INTERSECT и подзапрос / UNION ALL с фильтром.

SELECT nickname
FROM hackathon_2024
WHERE nickname IN (SELECT nickname FROM hackathon_2025)
  AND (
      score >= 90
      OR EXISTS (
          SELECT 1 FROM hackathon_2025 h5
          WHERE h5.nickname = hackathon_2024.nickname
            AND h5.score >= 90
      )
  );

Среди участников обоих лет (pixel_fox, code_ninja, byte_bard) балл ≥ 90 хотя бы раз дают code_ninja (92 в 2024) и pixel_fox (90 в 2025).

Итог

code_ninja, pixel_fox

Контрольные вопросы

  1. Чем UNION отличается от UNION ALL?
  2. Можно ли заменить IN (подзапрос) на EXISTS?
  3. Когда подзапрос в FROM удобнее, чем JOIN?
  4. Что делает коррелированный подзапрос особенным?
  1. UNION удаляет дубликаты строк в объединённом результате; UNION ALL — нет.
  2. Часто да (семантика «есть совпадение»), но синтаксис и NULL могут вести себя по-разному — проверяй на данных.
  3. Когда нужна промежуточная агрегация или «снимок» логики, который потом присоединяют.
  4. Внутренний запрос использует столбцы внешней строки и пересчитывается для каждой такой строки.
