📋 Задача: Проектирование БД для HR-платформы

Закрепление связей: One-to-One · Many-to-One · Many-to-Many

📖 Легенда и сущности

Ты — архитектор БД. Нужно спроектировать ядро сервиса по поиску работы (аналог hh.ru).

Основные сущности: Пользователь, Профиль соискателя, Компания, Вакансия, Навык, Отклик.

📌 Бизнес-требования

1. Пользователь ↔ Профиль. У пользователя есть email, пароль, дата регистрации. Он может создать себе профиль соискателя (зарплата, опыт, портфолио). 1:1
2. Компания → Вакансии. Компания (название, сайт, сфера) публикует вакансии. Вакансия всегда принадлежит только одной компании. N:1
3. Вакансия ↔ Навыки. Навык ("Python", "SQL", ...) требуется во множестве вакансий, и одна вакансия требует множество навыков. N:M
4. Соискатель ↔ Вакансия (Отклики). Соискатель откликается на много вакансий, у вакансии много откликов. У отклика есть дата и статус (рассматривается / отказ / интервью). N:M

🎯 Твоё задание

  1. Определить сущности — какие таблицы понадобятся.
  2. Описать связи, явно указав тип: 1:1 / N:1 / N:M.
  3. Спроектировать таблицы: названия таблиц и полей, PK для каждой, FK где есть связи.
    💡 Подсказка: связь N:M реализуется через промежуточную таблицу. Подумай, куда деть доп. данные отклика (дата, статус).
  4. (Опционально) Написать CREATE TABLE для 2 самых сложных таблиц.
